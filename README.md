# QR Check Toolkit · 二维码标签校验工具集

面向生产线二维码标签的桌面校验工具。扫码枪接入 Windows 电脑，逐张扫码实时判定：**重码拦截、规则校验、异常锁码**，记录落本地数据库可导出。

从「验重」到「规则引擎」的两代演进，一套代码两种用法：

| | **v1-dup-checker** | **v2-rule-engine** |
|---|---|---|
| 版本 | 1.1 | 2.0.0 |
| 解决的问题 | 已打印的几百张标签里有没有重码 | 每类料号的编码规则是否被打印模板遵守 |
| 判定依据 | 码本身是否扫过 | 料号 + 多条件规则 |
| 配置能力 | 无（零配置即用） | 规则管理 / 条件编排 / 导入导出 |
| 报警动作 | 声光提示 | 放行 / 提醒 / 拦截 / 锁码 / 锁屏 |
| 自检项 | 44 项 | 114 项 |
| 适用场景 | 一次性清点、发货前复检 | 日常打印工序的常态化卡口 |

两代**互不依赖**，可分别独立部署。v2 向后覆盖 v1 的验重能力。

## 快速开始

### 直接运行（现场电脑没有 Python）

从 **Releases** 下载 `QRCheck.exe`，双击即可。单文件版首次启动会自解压，约 2–3 秒。免安装、不写注册表、数据落在 exe 同目录的 `data/` 下，整个文件夹拷走即完成迁移。

### 从源码运行

```bash
# v2 规则引擎
cd v2-rule-engine
python main.py                 # 正常界面
python main.py --selftest      # 逻辑自检（结果写入 data/selftest.log）
python main.py --demo          # 演示模式（临时库，自动灌样本）

# v1 验重工具
cd v1-dup-checker
python qr_dup_checker.py
python qr_dup_checker.py --selftest
```

环境要求：**Python 3.9+**，仅需标准库（`tkinter` / `sqlite3` / `winsound` / `wave` / `csv` / `zipfile`）。
唯一的第三方依赖是 `pyserial`，**仅在使用串口模式扫码枪时需要**；HID 键盘模式（绝大多数 USB 扫码枪出厂默认）无需任何依赖。

界面里按 `F10` 可在 HID / 串口之间切换。

## v2 核心设计

### 规则识别：先认料号，再校验内容

一条规则由「识别方式」决定它管哪类码，再对该类码执行条件校验。

| 识别方式 | 说明 | 适用 |
|---|---|---|
| `PREFIX` | 以指定前缀开头 | 料号固定在码首，最常见 |
| `REGEX` | 正则匹配 | 编码结构高度不规则时 |
| `SEGMENT` | 按分隔符切段后取某段比对 | 结构化码（如 `%` 分段码） |

按 `priority` 数值小的优先命中；同优先级有前缀互相包含时，保存即提示冲突。

### 11 类校验条件

| 类型 | 含义 | 备注 |
|---|---|---|
| `CONTAINS` | 包含子串 | `*` `+` `%` 一律按字面量匹配，不做正则或 URL 解码 |
| `NOT_CONTAINS` | 不包含子串 | |
| `STARTS_WITH` | 开头是 | |
| `ENDS_WITH` | 结尾是 | |
| `EQUALS` | 完全等于 | |
| `REGEX` | 正则匹配 | 标记为「危险」，需二次确认 |
| `LENGTH` | 长度在区间 | |
| `CHARSET` | 只允许这些字符 | 能直接抓出混入中文、全角、不可见字符的脏码 |
| `SEGMENT` | 分段取值比对 | 保留空段（`%%` 切出空串而非被吞），否则段号整体错位 |
| `DATE_VALID` | 分段日期有效 | 支持 `YYMMDD` / `YYYYMMDD` / `YYYYMM` |
| `DATE_MATCH` | 两段日期一致 | 抓模板拼装串号 |

多条条件支持 `AND` / `OR` / `AT_LEAST(n)` 组合。单条条件可设置独立失败动作，**覆盖**规则级动作（而非取更严），便于「某条只是提醒、其余拦截」。

### 5 档动作

| 动作 | 表现 |
|---|---|
| `PASS` | 绿灯放行 |
| `WARN` | 允许继续，记录并标黄 |
| `BLOCK` | 拒绝，需重新扫码或人工确认 |
| `LOCK_CODE` | 该码进入锁码名单，后续扫码直接拒绝，需密码解锁 |
| `LOCK_SCREEN` | 锁定界面：吞掉 Alt+F4 / Alt+Tab / Win / Ctrl+Esc / PrintScreen，被杀后由看门狗 3 秒内重启 |

可配置**升级策略**：同类异常在 N 次 / M 分钟内出现则自动升档（如提醒 → 锁屏）。

### 两个刻意的设计取舍

**① 未匹配任何规则时，默认 BLOCK 而不是放行。**
现场每天新增约 50 个料号，若默认放行，新料号会静默漏检；若默认锁屏，则会频繁误锁、直接打死产能。取中间值：拦截但不锁屏，提示「未匹配规则」让班长 30 秒内补规则。宁可拦一下，不让错码流下去。

**② 识别阶段禁用 `CONTAINS`。**
用宽匹配认料号，一旦某个前导片段重叠，就会把 A 料号的码吸进 B 料号的规则里，然后用 B 的条件去"校验通过"——这是最危险的假阴性。识别只允许 `PREFIX` / `REGEX` / `SEGMENT`。

## 自检

核心判定逻辑与界面解耦，可无界面跑：

```bash
cd v2-rule-engine && python main.py --selftest
# 结果写入 data/selftest.log
```

覆盖归一化、条件求值（含空段/越界/脏字符）、料号路由、前缀冲突、密码哈希、跨终端验重的唯一性约束、规则导入导出往返。**当前 114 项全部通过。**

v1 对应 44 项，覆盖扫码枪数据分片拼接、UTF-8/GBK 中文、超长码丢弃、双列归一化验重等。

> 串口相关自检项需先 `pip install pyserial`，未安装时该项会显示 FAIL，不影响 HID 模式使用。

## 构建 exe

```bash
pip install pyinstaller
cd v2-rule-engine
pyinstaller --onefile --windowed --name QRCheck main.py
```

单文件版与目录版（`--onedir`）各有取舍：单文件便于分发，目录版启动更快。程序内用 `sys.executable` 的父目录定位数据，规避单文件模式下 `__file__` 指向临时解压目录的坑。

## 已知限制

- **锁屏强度分档，需如实告知现场**：A 档（钩子吞快捷键）挡不住 `Ctrl+Alt+Del`、`Win+L`、注销、拔电源；B 档看门狗只在进程被杀后重启，不阻止退出；C 档 Windows Kiosk 模式锁得最死，但需要企业版/教育版授权。**不要承诺"绝对无法关闭"**。
- **仅在 Windows 上可用**：`winsound`、低级键盘钩子、窗体 API 均为 Windows 专有。
- 串口模式依赖 `pyserial`；HID 模式零依赖。
- 大字符集扫码枪若关闭了中文输入法兼容层，可能丢字符，建议现场用实际标签先试扫。

## 路线图

- **P1（已完成）**：单机版规则引擎，本地 SQLite，跨批次验重。
- **P2（规划中）**：联机版。服务端（车间常开 PC / 工控机，固定内网 IP，开机自启）+ 多终端接入，实现跨终端验重、规则统一下发、远程解锁、判定权上收服务端；断网自动降级为单机继续可扫。

P2 的关键不在同步，而在**判定权威**：验重必须靠数据库唯一约束的原子性，不能靠应用层先查后写，否则两终端同时扫码会双双通过。

## 技术选型说明

- **纯标准库优先**。现场电脑是生产设备，装不了运行时、也没有外网，任何第三方依赖都是部署阻力。GUI 用 `tkinter`，存储用 `sqlite3`，报警音用 `winsound` + `wave` 生成，导入用 `zipfile` + `ElementTree` 直解 XLSX。唯一例外的 `pyserial` 仅串口模式需要。
- **SQLite 开 WAL**。扫码是高频短事务，多终端共享数据文件时 WAL 的并发读写远优于默认 journal 模式。
- **验重双列归一化**。同时存原始键与大写键，避免现场因大小写模式切换导致比对口径分裂。
- **判定权在服务端（P2）**。单机版的判定在本地，联机版必须上收，否则规则版本不一致会各自判各自的。
